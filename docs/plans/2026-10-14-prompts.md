# Plan: two MCP prompts built from existing tools

- **Severity:** P2 (agent usability and conversion)
- **Effort:** S

## Finding

- The server registers tools and resources but **no prompts** (no `registerPrompt` in `src/`). Clients that show prompts (slash-commands in Claude Desktop and others) offer users nothing.
- The two most common buyer questions can already be answered with existing tools, but agents have to work out the call sequence themselves.

## Proposed fix

New `src/prompts.ts`, called from `buildServer` in `src/server.ts`. Declare `prompts: {}` in the discovery capabilities.

1. **`compare_plans`**
   - Argument: `market` (optional, default `international`; one of the market codes).
   - Message text tells the model to:
     - call `udaybooking_get_pricing` with `{market, include_page_text: true}`
     - call `udaybooking_get_faqs` with `{source: "pricing", market}`
     - present a plan table (Free / Professional / Enterprise), quoting prices and limits **only** as returned, and saying Enterprise is quoted
     - cite the `source_url`
     - not estimate or convert prices.
2. **`is_udaybooking_right_for_me`**
   - Arguments: `business` (required, free text such as "2-chair dental clinic"), and `needs` and `market` (both optional).
   - Message text tells the model to:
     - call `udaybooking_get_site_summary` to orient
     - call `udaybooking_search_content` for the user's needs (team scheduling, reminders, payments, integrations ...)
     - read the top one or two pages with `udaybooking_get_page`
     - check `udaybooking_get_automation_capabilities` for limits
     - answer fit / partial fit / not a fit, with cited pages, and list any unknowns honestly
     - end with next steps (`udaybooking_get_started` if that tool exists, otherwise the pricing page).

Both prompts reference only tools that exist. A test enforces this, so renaming a tool breaks the build rather than the prompt. No customer data, no prices in the prompt text.

## Tests to add

`tests/prompts.test.ts`, using a real client over `InMemoryTransport`:

- `listPrompts()` returns both prompts with descriptions and arguments.
- `getPrompt` interpolates the arguments.
- Every `udaybooking_*` name mentioned in the prompt text is in `TOOL_NAMES`.
- `business` is required for the fit prompt.

## Risks, rollout, decisions

- If the `udaybooking_get_started` plan is not approved, the fit prompt falls back to the pricing link.
- **Founder:** the prompt names and titles as shown in client UIs.
